= Architecture

== Components

* **issuesbrowser (library)**: Types, git discovery, SQLite schema, forge sync, gitignore helper.
* **application (GUI)**: DlangUI app; repo list, issue/discussion list, detail view, sync trigger.
* **cli**: Command-line interface for sync, list, search, and archive discovery.

== Naming

The product is an *offline browser/archive*, not a tracker for creating tickets. Forge-agnostic naming (`issues-browser`) leaves room for GitLab and others; the first sync backend is GitHub via `gh`.

== Git discovery

Recursive walk of the given folder: any directory that contains a `.git` (file or directory) is treated as a repo. Remote URL, host, owner, and name are read from `.git/config`.

Username-level catalogues named `.issue-submissions` and nested `.issues` directories are skipped during repo discovery so personal submission trees are not mistaken for project clones.

Archive discovery walks for `**/.issues/database.sqlite` only (not every `.issues` folder).

== Database schema

* `repos`: path, remote, owner, name, host, updated_at.
* `issues`: repo_id, number, title, state, body, url, created_at, closed_at, author, pr_accepted, state_reason.
* `comments`: issue_id, body, author, created_at.
* `discussions`: repo_id, number, title, category, body, url, created_at, author.
* `discussion_comments`: discussion_id, body, author, created_at.
* `sync_meta`: repo_id, last_sync.

One SQLite file per repo: `<repo>/.issues/database.sqlite`.

=== Bodies in SQLite

Issue and discussion bodies stay in SQLite. For typical personal/org archives this is efficient and keeps search simple. The expensive part of huge upstreams (e.g. busy forks) is *API sync volume*, which is why guardrails exist. Splitting bodies onto the filesystem is reserved for a later optimization if a measured need appears.

== Sync process

. GraphQL preflight: issue/discussion/PR counts and fork/parent metadata.
. User confirmation when thresholds or fork risk apply.
. Ensure `<repo>/.gitignore` contains `.issues/`.
. REST: `gh api repos/owner/repo/issues --paginate --state all` (PRs skipped unless `--include-prs`).
. Per issue: timeline (close reason) + comments.
. GraphQL: discussions + comments (paginated); skipped cleanly when Discussions are disabled.
. Upsert into SQLite; record `sync_meta.last_sync`.

Background/timer sync in the GUI remains a future enhancement.
