= Usage

== GUI

. Start the application (`dub run --config=application` or the installed `issues-browser-gui` executable).
. Enter a path to a folder that contains git repos.
. Click *Add folder* to discover repos.
. Select a repo and click *Sync selected*. Large or forked repos ask for confirmation first.
. Click an issue or discussion in the middle list to view body and comments.
. Use *Refresh list* after adding a folder or syncing.

== CLI

*Discover repos:*

  issues-browser --add-folder /path/to/parent/folder

*Find existing archives (`**/.issues/database.sqlite`):*

  issues-browser --find-dbs /path/to/code/root

*Sync one repo or all repos in a folder:*

  issues-browser --sync /path/to/repo
  issues-browser --sync /path/to/folder/containing/repos
  issues-browser --sync /path/to/busy-fork --yes
  issues-browser --sync /path/to/repo --no-discussions
  issues-browser --sync /path/to/repo --include-prs

*List / search:*

  issues-browser --list /path/to/repo
  issues-browser --list /path/to/repo --search "antora"

*Help:*

  issues-browser --help

== Where data is stored

For a repo at `parent/reponame`, the SQLite file is at `parent/reponame/.issues/database.sqlite`.

On first sync the app appends a commented `.issues/` entry to that repo's `.gitignore` when missing.

Legacy path `parent/.issues/<reponame>.sqlite` is migrated automatically when present.

== Sync guardrails

Before downloading bodies, sync queries issue/discussion counts (and fork status).

* Soft warning around **500** issues+discussions.
* Strong confirmation around **2000** issues+discussions.
* Forks at/above the soft threshold always require approval.

Pass `--yes` (CLI) to approve non-interactively. GUI uses a Yes/No dialog.
